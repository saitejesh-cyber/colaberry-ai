## SEO Coverage

### seoTags() Usage
**29 of 30 public pages implement seoTags()**

| Status | Pages |
|---|---|
| ✅ Implemented | 29 pages — homepage, all catalog/detail pages, resources, forms, policies |
| ❌ Missing | `industries/[industry].tsx` — no seoTags() or JSON-LD |

Each `seoTags()` call generates:
- `<title>` and `<meta name="description">`
- `<link rel="canonical">`
- Open Graph: `og:title`, `og:description`, `og:type`, `og:url`, `og:image`, `og:site_name`
- Twitter: `twitter:card` (summary_large_image), `twitter:site`, `twitter:title`, `twitter:description`, `twitter:image`

### Canonical URLs
Automatically generated by `seoTags()` via `canonicalUrl()` helper. Base URL from `NEXT_PUBLIC_SITE_URL` (fallback: `https://colaberry.ai`). Dynamic slugs produce unique canonicals.

### robots.txt
✅ Implemented at `src/pages/robots.txt.ts` (SSR, cached 1hr)
- `User-agent: *` — Allow all
- `Disallow: /api/` — Block API routes
- `Allow: /llms.txt` — Explicit LLM index file
- `Sitemap:` directive present

### sitemap.xml
✅ Implemented at `src/pages/sitemap.xml.ts` (SSR, cached 1hr)
- 40+ static routes with priority/changefreq
- Dynamic entries from CMS: agents, MCP servers, skills, use-cases, podcasts, articles, industries
- `lastmod` from CMS timestamps where available
- Deduplication logic prevents duplicate entries
- XML escaping for special characters

## Performance

### Image Optimization
| Pattern | Usage | Status |
|---|---|---|
| Next.js `<Image>` with `priority` | Homepage hero, solutions | ✅ |
| Next.js `<Image>` with `sizes` | PremiumMediaCard (`sizes="(min-width: 1536px) 28vw, (min-width: 1024px) 32vw, (min-width: 640px) 44vw, 95vw"`) | ✅ |
| Next.js `<Image>` with `quality` | PremiumMediaCard (90), homepage (90) | ✅ |
| EnterprisePageHero images | SVG backgrounds (inline), no raster optimization needed | ✅ |
| CMS-driven images | Loaded via `<Image>` or `<img>` depending on context | ⚠️ Mixed |

**Gap:** Some detail pages use `<Image>` without `sizes` attribute, relying on default behavior. Impact is minor since Next.js image optimization still applies.

### ISR / SSR Strategy
| Route Pattern | Strategy | Revalidation |
|---|---|---|
| Homepage, platform pages | ISR (getStaticProps) | 10 min |
| Catalog pages (agents, mcp, skills) | ISR | 10 min |
| Resources (books, case-studies, white-papers) | ISR | 1 hour |
| Updates | ISR | 6 hours |
| Podcasts (listing, detail, company, tag) | SSR (getServerSideProps) | On-demand |
| Search | SSR | On-demand |
| Detail pages ([slug]) | ISR with fallback | 10 min |
| API routes | Dynamic | N/A |

This is a well-designed caching strategy — high-frequency catalog pages refresh every 10 minutes, while more stable content pages revalidate hourly.

### Bundle Size Considerations
- Dynamic imports used for: `CookieConsentBanner`, `DemoRequestWizardModal` (SSR disabled)
- This prevents these large modal components from bloating the initial bundle
- All page components use standard Next.js code splitting

### Core Web Vitals Targets
| Metric | Target | Assessment |
|---|---|---|
| LCP (Largest Contentful Paint) | < 2.5s | ✅ Likely met — hero images use `priority`, ISR pre-renders pages |
| FID (First Input Delay) | < 100ms | ✅ Likely met — minimal JS on initial load, dynamic imports defer heavy components |
| CLS (Cumulative Layout Shift) | < 0.1 | ✅ Likely met — Next.js `<Image>` reserves space, fixed hero heights |

**Note:** These are estimated targets based on code patterns. Actual metrics require Lighthouse/PageSpeed Insights measurement in production.
